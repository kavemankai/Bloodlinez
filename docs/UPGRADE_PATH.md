# Bloodlinez upgrade path

Working product thesis: investigate supernatural inheritance through believable records, expose an identity fraud, and build the argument that decides the estate. The strongest payoff is a deduction the player can explain from evidence they found. This is a design direction grounded in the prototype, not a sales forecast.

## First-hour shape

These are target beats to measure with people, not observed timings or forced gates.

| Window | Player action | Intended payoff |
|---|---|---|
| 0–10 minutes | Verify Julian's household relationship from an original record | I understand my job and can prove one fact |
| 10–25 minutes | Read Margaret's account and compare dated identification | I noticed something the paperwork conceals |
| 25–45 minutes | Follow earlier names and test identifying features | My suspicion has a documentary trail |
| 45–60 minutes | Consult the standard of proof and submit a limited concern | My work changes the case; I want the explanation |

The implemented preliminary report can be submitted earlier. Avoid holding it behind a timer or requiring the player to complete every prompt. The deeper case remains available in any order.

## Production sequence

| Stage | Deliverable | Proposed decision gate |
|---|---|---|
| 1. Trust and opening — implemented | Fair evidence assignment, neutral claims, revision mode, case desk, notebook, optional leads, preliminary response, recoverable saves and keyboard inspection | Eleven automated suites pass; generated build matches source |
| 2. Fresh-player validation | Five observed sessions with the facilitator guide; independent blind persona reviews when their runner is available | Four of five understand the task and submit a supported concern without facilitator rescue; explain which evidence changed their theory; zero unrecoverable save loss |
| 3. Evidence presentation | Replace the 1925 Desmond and 2019 Julian placeholders with consistent period portraits; improve zoom, focus visibility and readable document alternatives | Players distinguish resemblance from identity evidence; verify mark positions at every supported size and keyboard route |
| 4. A focused demo | A coherent opening ending at the partner's response; concise premise, spoiler-safe screenshots and an invitation to continue | Observe voluntary continuation and collect unprompted descriptions of the hook; revise if interest depends on explaining the game outside it |
| 5. Production foundation | Separate case content from engine, validate chronology and evidence references at build time, add per-case saves and a repeatable content checklist | A second case can be authored without modifying Case 1 proof logic; both cases remain independently solvable |
| 6. Broader game | One second case with a different legal dilemma, followed by the firm's larger mystery | It produces a different reasoning task and emotional payoff; returning players understand the tools without replaying onboarding |
| 7. Release candidate | Consistent art and audio, usability/accessibility pass, platform packaging, verified credits/asset rights, demo and full-build QA | No known progression or save blockers; external players complete the advertised scope; platform and commercial requirements verified before release |

The small-cohort thresholds are proposed iteration gates, not statistical market validation. Do not infer likely sales from five testers.

## Highest-value opportunities after the first test

1. Make the discrepancy visible. Identity is the central mechanic, so finish its documentary art before spending on extra portraits or large quantities of background lore.
2. Make the player assemble the argument. The new discovered-person fields remove answer sentences that gave away the story. Only add richer claim composition if observed players need a more expressive way to state their deductions.
3. Let research change the working context. The preliminary response now pauses distribution. Future cases can use similarly specific consequences, such as a requested document arriving or a claimant responding to a substantiated objection.
4. Give each case a different reasoning problem. A second vampire identity puzzle risks repetition. Prototype a conflicting succession rule or an ambiguous beneficiary before writing a complete archive.
5. Use the firm as the returning hook. Preserve the optional Ashgrove trail, but make each estate satisfying on its own. Avoid requiring a sequel to understand the first case's resolution.

## Scope discipline

Keep the browser-based document investigation while testing whether it is enjoyable. An engine rewrite, multiplayer, unrestricted language-model grading, live-service progression and a large first release would add work before answering that question. Price, platform commitments, total case count and release date remain decisions for evidence from a tested demo and a production estimate.

## What is still unproven

Automated tests establish specific behavior, not mystery quality. This implementation has not established a measured sixty-minute session, independent blind solvability, human enjoyment, willingness to pay, or commercial demand. Record build IDs and observed behavior in the playtest review so the next changes solve demonstrated problems.
